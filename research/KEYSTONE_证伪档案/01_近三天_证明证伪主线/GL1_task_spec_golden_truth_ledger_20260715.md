# GL1 · 项目终局真相账本（黄金铁律 vs 未验证清单）

> 审查/指挥 agent 下发。**这是本项目此刻最重要的任务**（人类原话："最最最最最最最重要的问题"）。
> 目标不是再算一遍，是**终结反复翻烧饼**：把过去所有结论收拢成一本带口径、可复现、分级的真相账本。
> 大任务、一次做完、中途不打断，最后交审查 agent 逐行审。codex 工作量应数倍于以往单个任务。

## 0. 病根诊断（先认清再动手）

同一个问题被反复计算、每次答案不一样（KEYSTONE 活/死、QuoterV2 诚实/不诚实、W2 有毒/不毒、瞎买 −68%/+1.37%…）。
**根因几乎全是同一个:口径变了却没随结论写下来。** 常见变动口径:
- 执行延迟(30 分钟 vs 秒级) · 缺失数据处理(=−100%全损 vs 保留 unresolved) · 人群定义(全新池宇宙 vs KEYSTONE 选中子集) · 数据源(成交额/2 代理 vs 真储备;transfer 接收地址 vs 真持仓) · 幸存者偏差(只在"有成交"的币上测) · 样本窗口 · gas/尺寸假设。

**铁则:一个不带口径的结论不算结论。** 本账本对每条事实强制标注口径;口径不同的两个数**不算矛盾**,是两件事。

## 1. 任务分期（全部做完再交）

### 阶段一 · 文档普查(INVENTORY)
扫遍仓库中与 KEYSTONE / Base 左尾 / QuoterV2 / rug / 频率 / 容量 / EV / 天气门 / 聪明钱 相关的**所有** markdown、审计报告、诊断 JSON、预注册、脚本头注释。
产出 `doc_index`:每份文档的路径、日期、核心主张一句话、是否含可复现脚本/hash。

### 阶段二 · 主张抽取(CLAIM EXTRACTION)
对每条**反复出现的量化主张**(至少覆盖下列,可增补),把**历次出现的数值 + 当时口径 + 日期 + 出处**全列出来:
- KEYSTONE 的 edge(均值/去top1%/右尾) —— 历次值
- KEYSTONE 信号**频率**(每周/每月触发数,及其**时间分布**——人类指出它是"有时集中爆发、有时很稀疏",所以要直方图/时间线,不要单一均值)
- **容量/池深曲线**:单笔可吃多大量,滑点吃掉多少 edge(给尺寸→净收益曲线)
- **现实每月 $ 期望**(在各本金/各频率假设下)
- QuoterV2 诚实度(假阳性率、Wilson 上界)
- W2 毒性 与 KEYSTONE 在 W2 的真实表现
- 无条件"瞎买"基线
- rug 分类与比率(五证据)
- alpha 衰减(是否/多快)
- D5 / forward 监控 / 天气门 的边际
- RH 聪明钱跟单(若有历史结论)

### 阶段三 · 冲突根因诊断(WHY IT FLIPPED)
对每条**有过互相冲突答案**的主张,精确指出每次翻转的根因(上面 §0 那几类口径中的哪一个)。这一节直接回答人类的"为什么反复问同一问题答案却不同"。

### 阶段四 · 唯一固定口径下重核(RE-VERIFY)
定义**唯一权威口径**并对每条主张重核:
- 执行=毫秒/秒级自动化(出场 +1/+5/+15 块);缺失≠全损(只五证据确认且不恢复的 rug 才 −100%);有真成交用真成交,否则用**明确标注的**原子守卫报价;真储备/真持仓(非代理);人群定义写清(全宇宙 or KEYSTONE 选中子集);WETH 原生计价。
- **不许拿旧 markdown 互相背书**:要判 IRON,必须能从**原始数据或可复现脚本重跑得到一致结果**;只在单份老文档出现、无可复现锚点的,一律降 OPEN。

### 阶段五 · 分级账本(LEDGER)
输出一张总表,每行一条主张,列:
`主张 | 权威口径 | 分级 | 该口径下的答案(带不确定度) | 证据锚点(文件/区块/hash) | 历史为何翻转 | (若OPEN)什么能定它`
分级三选一:
- **IRON**:≥2 种独立方法/独立样本一致验证,口径固定,有可复现 hash,不会再翻。
- **PINNED**:过去翻烧饼,但在权威口径下现已钉死(附翻转根因)。
- **OPEN**:历史真答不了(或只有单源无锚点),仍需真钱/更多数据。

### 阶段六 · 两张清单(人类的核心要求)
1. **黄金铁律清单** = IRON + PINNED:今后不再重新litigate的既定事实(含频率分布、容量曲线、QuoterV2 假阳性上界、W2 结论、rug 比率等已钉死项)。
2. **未验证清单** = OPEN:按"对挣钱多重要"排序,每条注明**什么测试能定它**、以及**是历史可解 / 需极小额真钱(喂给 RM1) / 需更多时间数据**。频率的"未来不可知"若不可约,就明确列为不可约 OPEN,别假装能预测。

## 2. 交付物

1. `doc_index`(阶段一)。
2. 机器可读账本 JSON + 人可读 markdown 账本(阶段五整表)。
3. **黄金铁律清单** 与 **未验证清单** 两个独立文件(阶段六)。
4. **人话版摘要**(中文、尽量无术语、把表格/工程细节翻成人能懂):三段——"哪些是铁的事实 / 哪些还不知道 / 为什么我们以前反复得到不同答案"。
5. 冲突根因诊断表(阶段三)。
6. 可复现:重核脚本、固定 block、请求/响应 hash、产出 SHA256;新增 RPC 只允许用于**settle 具体 OPEN 项**且要有 ledger。
7. 回归测试(账本关键数值断言用 ==)。

## 3. 铁律
- 纯只读 + 重核;不下单/签名/广播/改 live/signals/Redis;executor 保持关闭;不自判 GO。
- RPC 用 prettiest-blue-aura(orbital 已死);缺证据不默认全损;报价永不单独充当成交证据。
- 每条事实必带口径;无锚点单源结论不得升 IRON。
- 一切可复现,产出 hash。

## 4. 审查 agent 终审保留
账本回来后审查 agent 逐行审:IRON 是否真有≥2 独立可复现锚点(不是旧文档背书)、翻转根因是否诊断准确、OPEN 是否被诚实保留(没偷偷升级)、频率是否给的是分布而非误导性均值、容量曲线是否有实测支撑。**分级最终由审查 agent 定,codex 不自我背书。**
