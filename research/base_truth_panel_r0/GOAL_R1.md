# R1 — 631 个持续池的原子来回深度实测

状态：`INSTRUMENT_FACT`。只读。不产生任何交易决策，不解锁 live。
前置：R0 真值面板（`census.cl_swaps` / `census.pools`）。

## 1 这一轮要回答什么

R0 证明了旧面板严重低估了 Base 的真实池宇宙（持续 WETH 腿池 **631 个**，旧面板只看得见 4 个）。
R0 没有回答的是：**这 631 个池能不能真的进出。**

具体三问：

1. 631 个池里，有多少能完成一次「买入 + 卖出」的原子来回？
2. 能完成的池，$50 / $250 / $1000 / $5000 各档来回成本是多少 bps？
3. 不能完成的，卡在哪一层——没有路由器、代币无法驱动、还是确定性 revert？

## 2 三个必须先修的仪器债

这一轮的一半工作量在修仪器，因为不修就会被同一个洞污染。

### 2.1 slot 探测：盲扫 → 访问列表

旧实现（`base_f03_atomic_r0/src/atomic_engine.py`）盲猜 `keccak(owner, slot)`，slot 取 0..39，两种布局。
它在 f03 上留下 **19.4% `INFRASTRUCTURE_UNKNOWN`**，当时归因为「代理合约」。

真实病因不是代理，是**基槽根本不在小整数区间**：ERC-7201 命名空间存储（OZ v5）的基槽是个哈希值，Solady 用自定义 seed。扫得再宽也碰不到。

新实现（`src/slot_detect.py`）改为问链本身：`eth_createAccessList` 返回该次调用实际访问的存储槽，再逐个覆盖验证哪个真的改变了返回值。与布局无关。

实测（631 池的 410 个 alt 代币里随机抽 60 个）：

| | 旧盲扫 | 新访问列表 |
|---|---|---|
| 解决率 | ~80.6%（f03 实测） | **98.3%**（59/60） |
| 每代币 RPC 调用 | 最多 80 | **4.2** |

USDbC / cbETH 这类旧方法完全做不到的，新方法一次命中：它们的余额槽是 `0x8df201bd…`，
而 `0x360894a1…`（EIP-1967 实现指针）会被显式排除。

失败不再静默，分三类：`EXTERNAL_STATE_DEPENDENT`（余额依赖外部合约，如 Aave aToken 的
流动性指数在 Pool 里）、`NO_CODE`、`SLOT_NOT_CONFIRMED`。

### 2.2 路由器：一个 → 按工厂映射 11 个

CL 路由器用**自己的** immutable factory 反推池地址，所以工厂 X 建的池在绑定工厂 Y 的
路由器上不可达。这是之前 aero_cl 池 `BUY_REVERT` 的真因，不是流动性问题。

目标集里有 21 个工厂。`src/discover_routers.py` 用「读池子自己的调用方，
留 `factory()` 对得上的那个」自动发现，无需逐个分叉查地址：

| 工厂 | 池数 | 路由器 | 来源 |
|---|---|---|---|
| `0x33128a8f…` univ3 | 374 | `0x2626664c…` | seed，已验 |
| `0x5e7bb104…` aero_cl | 137 | `0xBE6D8f0d…` | seed，已验 |
| `0xf8f2eb49…` aero_cl | 24 | `0x698Cb2b6…` | seed，已验 |
| `0xade65c38…` aero_cl | 24 | `0xcbBb8035…` | **发现** |
| 其余 7 个分叉 | 35 | 见 `out/router_map.json` | 发现 |
| 10 个冷门工厂 | 37 | 无 | `NO_ROUTER` |

覆盖 **594/631 = 94.1%**，代价 154 次 RPC 调用。

### 2.3 深度口径：两次独立调用 → 单次调用内来回 → **单向对中间价**

这一项试错了两次，记全。

**第一版（R0 深度普查）**：买入和卖出**分开模拟**，卖出打在未被买入推动的池子上。不是来回。

**第二版（R1 第一稿）**：用 Multicall3 把 `[buy, sell]` 放进同一个 `eth_call`，池状态从买入
延续到卖出。当时把「fee=100 的池恰好 2.0 bps、fee=500 的池恰好 10.0 bps」当作正确性证据。

**那恰恰是它无效的证据。** CLMM 里同池来回是沿同一条流动性曲线原路返回，**价格冲击按
数学恒等式精确抵消**，与池子薄厚完全无关。所以这个度量恒等于 2×费率，测的是费率档，
不是深度。压力测试确认：88 天仅 1,762 笔成交的池，$500,000 来回只要 1.1 bps。

**第三版（定稿，`src/slippage_631.py`）**：**单向**成交价对池内中间价的偏离。
中间价取 `slot0().sqrtPriceX96`，在 raw 单位下比较，与 decimals 无关：

```
want = amt_in * mid   (WETH 为 token0)  |  amt_in / mid  (WETH 为 token1)
slip_bps = (1 - actual_out / want) * 10000
```

行为验证（这次是真的验证——它必须随金额增长）：WOLF（1,762 笔）$50 = 16 bps → $100k = 7,510 bps；
USDC（330 万笔）$50 = 1.0 bps → $100k = 72 bps。薄池爆炸、厚池平缓，符合物理。

## 3 两个数字各是什么

**单向滑点（主度量）**：一次进场或一次出场对中间价的真实成本，含手续费。随金额增长。

**费率地板（副产品，来自已废弃的来回度量）**：2×费率。任何进出一次的策略的下限。
保留在 `out/slippage_631.tsv` 的 `fee_floor_rt_bps` 列。

**两者都不是**持仓过夜的成本：真实交易两腿隔着时间，池状态会变，还要付逆向选择。

## 4 冻结口径

- 目标集：`census.cl_swaps` ⋈ `census.pools`，WETH 腿，`n_days>=60 AND n_swaps>=1000` → 631 池
- 单块快照：`head - 20`，全部池同块，避免跨块比较
- ETH 计价 $4000（固定，仅用于换算档位，不影响 bps）
- 档位：单向滑点 $50 / $500 / $5,000 / $25,000 / $100,000；费率地板 $50 / $250 / $1000 / $5000
- 产出：`out/slippage_631.tsv`（主）、`out/slippage_631.json`、`out/depth_631.tsv`、
  `out/depth_631.json`、`out/router_map.json`、`out/targets_631.tsv`、`out/alt_symbols.json`
