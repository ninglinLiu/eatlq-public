## 1. 已核实的事实基线

### 1.1 本轮只回答三件事

1. 点时分数能不能在不看见结果的情况下写下来（空分合法，回填非法）。
2. 「同一梗、多个合约」的克隆表能不能建起来；「再发一个牛来」是不是历史上反复出现的结构。
3. 15–30 个事件里，**M 高而 I 塌**的模式是否出现。

正式四条裁决（见 §5）在本样本量下默认 `UNDERPOWERED`。

## 2. 抽样框（章程核心）

先事件，后合约。15–30 指**事件**，不是代币。每个事件再挂克隆合约。

### 2.1 预登记配额（锁在 `events/EVENT_UNIVERSE.md`）

收数前必须锁死，并核对：

- ≥5 个 Web2 / 文化渗漏事件，**必须含牛来**（识别案例）。
- ≥5 个链原生梗（pump / Clanker / 链内吉祥物）。
- ≥5 个近失或「有搜索词但没粘住」的事件。
- ≥3 个政治 / 身份类。
- 事先已知名的超级赢家事件 ≤ 全部事件的 40%。
- 每个事件必须写出 `t0`：搜索词出生的理由与时间锚；**该段落禁止出现 ATH、上所、百倍、涨幅。**

### 2.2 合约收集规则

- 按搜索词在 DexScreener（及 Base CH / Sol JSONL）枚举同名、近名、同图合约。
- 按创建 / 首池时间取前 **N=10**（预登记）。
- 赢家不是抽样单位，只是事后标签（写在 `outcomes.csv`）。

### 2.3 流程

```
search_term_born_T0
  → freeze EVENT_UNIVERSE
  → read_only_name_search
  → score M on event, I/S/E on contract
  → freeze scores.csv
  → label attach / righttail / extractability
  → R0_PILOT (descriptive only)
```

宇宙未锁，不得收数。牛来是第一个必须跑通的收集冒烟，不是唯一事件。

## 3. 点时打分卡（20 维）

分值域：`高` | `中` | `低` | `空` | `否`。点时答不上来标 `空`。

### 3.1 M — 梗（事件级）

| ID | 名称 | 点时问题 |
|---|---|---|
| M1 | 注意力预存 | 链外是否已经有一群人在搜、在谈、在转发这个词？ |
| M2 | 可复制性 | 一个陌生人 10 秒内能不能重做图、重造句、重发明星？ |
| M3 | 焦点唯一性 | 有没有一张图、一句话、一个 ticker 是显而易见的那个？ |
| M4 | 跨域渗漏 | 热度是从 Web2 / 院线 / 政治进来的，还是只在币圈内部循环？ |
| M5 | 反审美 / 冒犯 | 是否粗糙、荒诞、「不该上链」因而更好转？ |
| M6 | 热度加速度 | 打分这一刻，搜索和转发还在加速，还是已经见顶？ |
| M7 | 名字即欲望 | ticker 是愿望词还是已完成的身份符号？ |

### 3.2 I — 发行权（合约级）

| ID | 名称 | 点时问题 |
|---|---|---|
| I1 | 谢林合约 | 这个词是否已经粘在一个被公开指认的地址上？ |
| I2 | 发行者类型 | anon / 已知部署集群 / KOL / 交易所邻近 / 官方邻近？ |
| I3 | 注意力所有权 | 发行者是否已有会看他合约的人群？ |
| I4 | 库存能力 | 有没有人拿得出第一笔不可假装的价格路径？ |
| I5 | 同名密度 | 同一时刻有多少个同名/同图/同梗合约？ |

### 3.3 S — 盘口（合约级）

| ID | 名称 | 点时问题 |
|---|---|---|
| S1 | 内部浮筹 | 前排 / 部署者 / LP 是否仍握着能砸死叙事的仓？（代理；不知则空） |
| S2 | 指定后排 | 故事里下一批买家是谁？ |
| S3 | 路径阶段 | 无名 / 第一针 / 派发 / 第二腿 / 复盘？ |
| S4 | 链与场匹配 | 梗的观众是否本来就生活在这条链？ |

### 3.4 E — 兑现（合约级，默认观察者）

| ID | 名称 | 点时问题 |
|---|---|---|
| E1 | 你的轨道 | 该链上默认观察者有没有预置弹药与路由？ |
| E2 | 延迟税 | 从注意到到能成交，要过多久？ |
| E3 | 可卖性 | 税、蜜罐、撤池、买得进卖不出的门开着吗？（不知则空） |
| E4 | 深度对尺寸 | 计划仓位是否小到不改写盘口？（默认彩票仓；不知则空） |

## 4. 三个结果（分数冻结后才算）

写在 `outcomes.csv`，**不得回写 scores**：

1. **粘住 (attach)**：同梗合约窗口内，是否有一个吸走了大部分成交 / 搜索指向。
2. **右尾 (righttail)**：该合约是否出现过大的市值 / 价格右尾（只作标签，不作交易）。
3. **兑现结构 (extract)**：税 / 撤池 / 能否观察到卖出成交。不是「我们模拟买了会怎样」。

## 5. 预登记裁决（功效声明）

若未来更大样本出现下列情形，按此裁决。**R0（n=15–30）只够描述模式，不够认证或证伪。**

| 若出现 | 裁决 |
|---|---|
| 点时 M 在克隆与近失里也能预测起飞 | 梗分数有资格独立存在 |
| 只有 I1 / I3 / I4 稳，M 只在事后好看 | 系统改名「发行权分数」；八点分析降级为燃料描述 |
| M+I 能预测粘住，但不能预测可兑现 PnL | 研究可继续，交易权关掉 |
| 任何点时组合都输给「已出现第一针」 | 梗分数作为交易工具死亡 |

R0 报告必须先写：`POWER = UNDERPOWERED`。
