# RT02 右尾验收规范

版本：`RT02-2026-10-01`  
状态：在任何新的收益测量之前冻结。标识器是 `rt02_accept.py`，冻结哈希在 `rt02_freeze.json`。  
本文件不测量市场收益，也不给任何旧策略恢复盈利主张。

## 四个估计对象

四个数不能互相代替：

| 对象 | 回答的问题 | 不能当成 |
|---|---|---|
| `wallet_pnl` | 源钱包自己的完整经济损益 | 我方能复制到的钱 |
| `our_copy_pnl` | 我方在观察和执行延迟之后的可实现全成本净收益 | 源钱包损益，或报价 |
| `selection_gain` | 相对匹配对照，选择器多出来的钱 | 市场暴露本身为正 |
| `holding_gain` | 同一批事前入场上，持有规则相对约定退出多出来的钱 | 选币能力 |

认证对象必须在计算前写明。缺省时标识器拒绝认证。

## 主目标

主目标是指定对象的可实现全成本净收益，按真实时间顺序加总。单笔胜率、标签名称、中位数、每个短窗口为正、去掉最大赢家后仍为正、利润必须分散，都不是主目标。

这些诊断必须输出，但不能单独否决：

- 胜率
- 中位数
- 按事件去掉最大集群后的净额
- 最大事件占净额的比例
- 分窗口净额

仍然必须单独通过、缺了就不能认证的项目：

- 事前选样，入场信息早于结果
- 费用、冲击、观察延迟和资金占用已经进净额
- 卖出是可实现的，不是池子报价
- 期初库存完整；超卖没有被编成成本
- 未知退出单独列示，不删除，也不写成已确认全损
- 并发超过账户资金的单子记为没做，不混进已做组合的盈亏
- 相对匹配对照的选择增益，和绝对净额分开认证

正的样本均值只说明绝对净额这一项。它不认证选择增益，也不在有未知退出或库存缺失时认证。

## 旧门槛映射

旧门槛保留原义。本规范不改历史报告，只规定它们以后在右尾认证里扮演什么角色。

| 旧门槛 | 出处 | 新角色 |
|---|---|---|
| 用 1 日 / 7 日 / 30 日盈亏或胜率排序当入场 | `copy_cascade_invert_r0/CHARTER.md` | 仍然禁止当入场。只能作为事前候选信息，而且必须在看到后续收益之前冻结 |
| 胜率本身 | 同上；标签脚本不计算经济胜率 | 诊断。低胜率、净额为正，必须被认成绝对净额成立 |
| 中位数为正、每窗为正、去顶后仍为正、利润分散 | 历次复制与稳健性检验 | 诊断，不是通用否决 |
| `top1_profit_share < 50%` 才有资格 | Base RH1 去集中门 | 资格规则若使用，必须在分布冻结时写死。看到零名单后不准放宽。它不是收益认证 |
| Arm B `permute_weaker` | `arm_b.json` | 保留，属于选择增益。绝对均值高于零但不能打赢打乱对照，仍然失败 |
| 看到结果后降低 `k` | Arm B 与章程 | 仍然禁止 |
| 缺失退出记 −100% | KEYSTONE 旧口径，已被同一批数据推翻 | 禁止。未知保持未知 |
| 报价等于我方成交 | R2 上 `atomic_net_return_h` 与 QuoterV2 相关为 1，因为标签相同 | 禁止。`quote_only` 不能进入成功 |
| Smart Money = 买入低于代币 tick 的 p10 且卖出高于 p90 | `compute_labels.py` `compute_smart_money` | 这是价格位置标签，不是盈利标签，不能当成功 |
| Diamond Hand 文档写持有超过 30 天，SQL 实际是 `>= 14` 天 | 同文件 `compute_diamond_hand` | 标签与实现不一致。两者都不是持有增益。持有增益只按本规范的 `holding_gain` |
| 仪器预检的费率来源、30% 集中度、年化万倍 | `preflight/preflight.py` | 继续管「表观收入」类研究。不代替本规范的右尾净额 |

## 组合与压力

1. 已执行的单子按 `time` 排序，净额累加，得到资金路径。
2. 同一 `event_id` 是一个集群。重复交易同一金狗不能把集群数算成多笔独立成功。
3. 输出集群数、最大集群份额、去掉最大集群后的净额。份额高或去顶后变号，只记诊断。
4. 未知单子留在分母里。点估计只使用 `confirmed_fill` 与 `confirmed_fail`。下界把未知换成亏掉全部名义，上界把未知换成 0。上下界是边界，不是两种已证实结果。
5. 存在未知、报价冒充成交，或期初库存不完整时，`certified` 为假。

## 标识器必须认出的三件事

由 `rt02_accept.py` 的夹具执行，不使用新的市场样本：

- 九笔各亏 1、一笔赚 20，全部确认成交且库存完整：胜率 0.1，净额 +11，绝对净额认证为真。
- 那一笔 +20 若只是未兑现报价：认证为假，原因 `UNREALIZED_QUOTE`。
- 净额为正但期初库存缺失：认证为假，原因 `OPENING_INVENTORY_MISSING`。
