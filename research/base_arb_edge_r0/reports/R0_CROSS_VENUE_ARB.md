# 1 测了什么

同一代币对在两个独立 CLMM 池之间的边际价格缺口，是否超过两条腿的执行成本。
不预测任何价格，不做空，不借贷。

宇宙：537 个有双向实测成本的池，按 alt 分组 → **86 个 alt / 726 个有序对**，
主宇宙为门槛 < 30 bps 的 **52 对 / 18 个池**。

时间范围：`block_number >= 46000000`（2026-05-14 → 08-17，94.6 天）。
**一年期回填正在写库，中段不完整，用它会造出假价格跳变。**

一个使度量有效的性质：**CLMM 的价格只在有人成交时改变**（流动性增减不移动价格），
所以"上一笔成交后的 `sqrt_price_x96`"就是当前边际价格。前向填充在这里**精确**。

# 2 四个阶段，每一阶段都推翻上一阶段的一部分

## 阶段一：分钟网格（52 对）

中位毛价差在**所有**对上都是 ~0.0 bps —— 池子平均对齐得很紧，机器人在工作。
p99 毛价差 0.9–23.4 bps，尾部存在。只有 USDC 的对净收益 p99 为正。
7 对的 `net>0` 分钟占比 ≥ 0.1%，最高 1.707%。

## 阶段二：区块网格 + 可执行性

**分钟分桶不是虚增而是低估。** 我事前担心两个池在同一分钟内的"最后成交价"
可能相隔 59 秒、价差是异步伪影；实测方向相反：区块级正占比 **2.926% > 分钟级 1.707%**，
因为取分钟末价会漏掉分钟内的缺口。

主指标（预登记）：在 b 观察到缺口，最快 b+1 成交。
最佳对 53,267 个信号区块，**net@b = 2.96 bps，net@b+1 = 2.28 bps，78.6% 仍为正**。

**这个度量在"竞争"这一维上自动正确**：若别的机器人在 b+1 内吃掉缺口，
b+1 结束时的价格就不再有缺口，net@b+1 会算成负。所以那 78.6% 是**确实没人来吃**的情况。

## 阶段三：手续费不是常数（推翻阶段二的成本）

从 CLMM 恒等式 `(1−f)·amount_in = L·Δ√p` 把实际手续费反解出来：

| 0xd0b53d92 | univ3 | 5.00 bps | 5.00 / **5.00** / 5.00 |
| 0x7c7420dd | aero_cl | 0.85 bps | 0.86 / **0.86** / 0.88 |
| 0x42d4a22c | aero_cl | 1.75 bps | 1.05 / **1.36** / 1.75 |
| 0xb2cc224c | aero_cl | 3.64 bps | 0.50 / **0.60** / 3.28 |
| 0x3fe04a59 | aero_cl | 3.98 bps | 2.66 / **3.65** / 4.97 |

**Uniswap 精确吻合到小数第三位，验证了反解公式本身。
Aerodrome Slipstream 的手续费是动态的**，`fee()` 只是我查询那一刻的快照。
把它当常数用在 53,267 个不同区块上是错的——而 1–2 bps 的费率摆动就是全部优势。

**这个错误同样存在于 R3 的点时成本模型里**（`pit_cost.py` 用了静态 `pl.fee`）。
Aerodrome 占本市场的多数池，所以 R3 必须修。

改用点时费率 + 点时闭式滑点后重测（方向无关的缺口定义，同时修掉阶段一/二一个
标签错位：`p = token1/token0` 时可获利路径需要 `p_X > p_Y` 且收益为 `(p_X−p_Y)/p_Y`）：

最佳对 88,522 个信号区块，**net@b+1 = 1.96 bps，79.3% 为正**。

## 阶段五：同一个缺口被数了几次（把优势砍掉 6 倍）

88,522 个信号区块**不是** 88,522 个机会。一个持续 40 个区块的错位是**一个**机会，
因为我自己的套利交易会把两个池的价格拉到一起、关掉它。

一个 episode = 信号区块的最大连续段（在**事件区块序列**上连续，

# 4 唯一能定生死的下一步（已执行，见 §6）

**在历史信号区块上原子模拟真实的两腿套利。**

用 `state-override` 授予 WETH 余额与授权，在历史区块 b+1 上：
腿一 `WETH → USDC`（池 A 的 router），取实际输出；腿二用该实际数量 `USDC → WETH`（池 B）。
`净 = (WETH_out − WETH_in)/WETH_in`。这是真值，不含任何模型。

抽样 200 个 episode × 2 次 `eth_call` = **400 次调用 ≈ 8,000 credits**。
便宜且完全决定性。

事前写死的裁决规则：
- 200 个样本的实测净收益均值 > 0 且按天分块 bootstrap 下界 > 0 → **`ARB_EDGE_CONFIRMED`**
- 均值 ≤ 0 → **`ARB_CLOSED_BY_BOTS`**，本族封死
- 实测与模型的差 > 1 bps → 模型作废，且 R3 必须连带修

# 5 尚未建模、会让结果变差的项

1. **抢跑**：历史数据无法settle。Base 用中心化定序器、按到达顺序排（无公开 mempool），
   所以抢跑比 L1 难；但与定序器同机房的专业搜索者一定比我快。
   **b+1 存活率 63.5% 只是上界。**
2. **gas**：Base 上两腿约 250k gas ≈ $0.02–0.05/笔。0.32 bps × $5,000 = $0.16/笔，
   **gas 吃掉 12–31%**。最佳对每天 232 笔，gas 是实质项不是零头。
3. **回滚保护会改善而非恶化结果**：真实套利合约会在链上算出输出、不达阈值就 revert，
   于是 36.5% 的负样本只付 gas 而非全额成本。本轮的无条件均值 0.32 bps
   **低估**了带 revert 保护的策略。这一项要在阶段六一起测。
4. **资本占用**：每天 232 笔、每笔 $5,000，若串行则 $5,000 本金即可周转。

## 6.2 撤回：我对 R3 的指控是错的，我的"修法"才是 bug

在同一个历史区块上把单腿成本对真值：

| 规模 | **实测** | 静态 `fee` 字段 + 闭式滑点 | 差 |
|---|---|---|---|
| $50 | 4.262 bps | 3.642 | −0.62 |
| $500 | 4.278 | 3.661 | −0.62 |
| $5,000 | 4.440 | 3.851 | −0.59 |
| $25,000 | 5.159 | 4.694 | −0.47 |

**静态字段的模型只差 0.6 bps，且滑点随规模的增长被正确捕捉。**
而我在阶段三用 CLMM 恒等式反解出的费率，对 `0xb2cc224c` 给出中位 **0.60 bps**，
而 $50 档的实测成本 4.262 bps 几乎纯粹是费率（该档滑点约 0.006 bps）
→ **真实费率约 4.26 bps，反解低了 3.6 bps**。两条腿就是 7 bps，这是那 12.29 bps 的主要来源。

**所以 `pit_cost.py`（R3）用静态 `fee` 字段没有错，我要撤回账本第 37 轮初稿里
"R3 有 bug、C1-R1 必须先修"这条结论。**

为什么反解会错：`f = 1 − L·Δ√p/amount_in` 是两个几乎相等的量之差，
要把 `f` 解到 0.1 bps 需要 `L·Δ√p` 有 1e-6 的相对精度。它在 Uniswap 池上给出
精确的 1.000 / 5.000（所以公式本身对），但**逐池可靠性必须先对原子实测验证，
不能假定**。这一条本身就是教训：**一个在部分样本上精确吻合的公式，不等于它在全体上可用。**

## 6.3 `ETH_USD = 4000` 是错的，影响所有历史轮次

三个独立的 WETH/USDC 池对价格一致到 **0.02%**（2026-05-14 三池分别报
2295.8 / 2296.3 / 2296.0 USDC per WETH）。面板期内 ETH 为
**1,475 → 2,302，中位 1,812**。

所有代码里的 `ETH_USD = 4000` 使 `1.25 WETH` 被当成 $5,000，实际约 **$2,265**。
后果：**R2 的滑点、R3 的点时成本、第 36 轮的做市名义与成本分层、本轮的门槛，
全部是对一个约一半大小的交易测的。** 费率项与规模无关不受影响，
但滑点项对真正的 $5,000 被低估约 2.2 倍——**在薄池上这是实质性的乐观偏差**。

这一条不改变第 35/36 轮的负面裁决（低估成本后仍然亏），
但它使那些裁决**比原先记录的更硬**，且任何未来用到名义规模的分析必须改用**点时 ETH 价格**。

## 6.4 三个池 0.02% 的一致性本身就是答案

这是本轮最简洁的一句解释：**在日频上，三个不同场地、不同费率档的 WETH/USDC 池
价格一致到 0.02%。** 套利者已经把这个市场压到几乎没有缝隙。
区块级还能看到 2.9% 的时间有超过费率带的缺口，但那些缺口在真实执行下
**全部**是负的——它们是执行成本的镜像，不是可取的钱。
