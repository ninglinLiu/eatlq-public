# 指挥简报：Base 聪明钱归因线 — 阶段结论与待决策

> 来源：审查型指挥 Agent（EATLQ 侧）　日期：2026-07-14　性质：只读研究，全程未下单/签名/改 live
> 一句话：**"识别单个聪明钱→跟单/狙击"这类策略在 Base 上先天缺地基，不是调参能救。建议指挥拍板下一步方向。**

## 1. 背景（一段话）
B1 已证明旧跟单失败主因是归因混淆（Router 坍缩），但当时高置信 tx_from 只覆盖 0.65%，无法自证。为把覆盖率救到 >90%，做了 B2（token 净流向反向归因）。经三轮逐行审查 + 链上 golden 核验，B2 的覆盖率救援**证伪**。

## 2. 核心发现：Base 订单流结构性难以按单钱包归因
三条独立证据：
1. **tx_from 只覆盖 0.65%**——Base 上 ~58% 交易走智能钱包/账户抽象，`tx_from` 是 bundler/EntryPoint，不是交易者。
2. **净流向法虚高**——一度做到 92% 覆盖，但挤水后：60% 落在合约钱包，其中头部是**共享合约/协议金库**（链上抓到 Balancer 金库被当成"聪明钱受益人"；某地址 199 个不同人签名打进同一处）。剔除已识别的共享合约后，能干净归到单个交易者的 swap **仅 ~47.8%，且仍不干净**。
3. **中转稀释**——即便在 EOA 上，56.7% 的买入币流向归集/中转地址而非决策者本人。

结论：tx_from 错、收币方常是共享合约或中转地址，两头都不是"交易者本人"。**这限制的是一整类策略（跟单、聪明钱狙击），不是单个 alpha。**

## 3. 当前状态
- Base 聪明钱策略 merit = **UNTESTED**（不是"没 edge"，是"没资格测"）。铁律维持：**不下"有/没有 edge"结论**。
- 已证伪：transfer-net 覆盖率救援（当前口径）。
- 未动 live、未改任何生产配置；所有结论可复现、带链上 golden 与 hash ledger。

## 4. 待指挥决策：下一步方向（三选一）
1. **转向不依赖钱包身份的信号**（推荐）：放弃"识别单个聪明钱"，转池/代币级结构信号（承接 2min-accel / keystone regime 两条在跑的线）。地基更稳，不受归因坍缩影响。
2. **诚实的 EOA 少数派**：只在干净的 EOA 切片（~25%）上验跟单，明确标注"少数派、有偏"，只作下限证据；需先补 PnL 链上 golden。
3. **深水区归因**：解析共享合约/solver 内部真实 end-user 或 call-trace 归因——工程量大、可能仍失败，需评估性价比。

## 5. 我的建议
选 1。Base 是智能钱包主导的市场，"逐钱包聪明钱"范式与该市场结构冲突；把精力放在不需要钱包身份的结构信号上，边际回报更高。若指挥坚持要聪明钱路线，则走 2 作最小诚实验证，不要投 3 除非有明确外部理由。
